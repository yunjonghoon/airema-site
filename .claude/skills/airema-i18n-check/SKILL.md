# 아이레마 번역 동기화 점검

3개 언어판(한국어 `x.html`, 영어 `x-en.html`, 일본어 `x-ja.html`)이 한 몸처럼 움직여야 하는 사이트다. 사람이 눈으로 18개 파일을 비교하면 반드시 놓치기 때문에, 비교 작업은 스크립트에 맡기고 Claude는 **결과를 해석해서 보고**한다.

## 사용법

1. 사이트 폴더(index.html이 있는 곳)에서 스크립트를 실행한다. 몇십 초에서 1분쯤 걸린다.
   ```bash
   bash .claude/skills/airema-i18n-check/scripts/check_sync.sh .
   ```
2. 출력은 6개 구역이다. 문제가 없는 구역은 아무것도 출력되지 않는다.
   1. **구조**: 페이지별 section, h2, h3, a, img, li 등의 개수가 ko/en/ja에서 같은지. 다르면 한 언어판에서 항목이 빠졌거나 더 들어간 것이다.
   2. **번역 누락**: 영어/일본어 페이지에 한글이 남았는지, 영어·한국어 페이지에 일본어 가나가 섞였는지.
   3. **언어 설정**: `<html lang>`, hreflang 3줄, 언어 선택 option 3개와 자기 언어 selected.
   4. **링크와 이미지**: 언어판끼리 같은 곳을 가리키는지, 참조한 파일이 실제로 있는지, alt가 비었는지.
   5. **캐시 값**: 모든 HTML의 `?v=` 값이 같은지.
   6. **번역 사전**: `site.js`의 한국어 문구가 `language-data.js`에 키로 있는지.
3. 결과를 사용자에게 보고한다. 문제마다 **어느 파일의 무엇이, 어떻게 고치면 되는지** 한 줄로 쓴다. 문제가 없으면 "문제 없음"이라고 짧게 말하고 끝낸다.

## 보고할 때

- 스크립트가 낸 줄을 그대로 붙이지 말고, 같은 원인으로 나온 여러 줄은 하나로 묶는다. 예를 들어 `?v=` 불일치는 어느 파일이 어느 값인지 한 문장으로.
- **이 스킬은 고치지 않는다.** 번역 문구를 새로 쓰거나 파일을 바꾸는 일은 사용자가 요청할 때 `airema-site-editor`로 한다. 점검과 수정을 섞으면 사용자가 무엇이 바뀌었는지 알 수 없다.
- 스크립트가 틀릴 수 있다. 의심스러운 줄은 해당 파일을 Grep으로 직접 확인한 뒤, 오탐이면 그렇다고 알린다.

## 스크립트가 일부러 넘어가는 것 (오탐이 아니라 의도)

- 언어 선택 상자의 `Language / 언어 / 言語`와 `한국어` — 항상 한글이 들어간다.
- 해동가적 낙관 이미지(`origin-korean-seal`, `origin-hanja`)의 alt — 원본 한글 표기를 일부러 유지한다.
- `site.js`에서 `currentLang===`로 언어별 문구를 직접 고르는 줄 — 사전을 쓰지 않는다.

이 목록에 없는 새 예외를 발견하면, 사용자에게 알리고 스크립트에 예외를 추가할지 묻는다.

## 점검하지 못하는 것

번역이 **맞는 뜻인지**, 어색하지 않은지는 스크립트가 알 수 없다. 개수와 구조, 남은 한글, 누락된 키만 본다. 번역 품질은 사용자가 따로 요청하면 눈으로 읽어서 검토한다.
